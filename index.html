Dynamic resource allocation. Provable system safety. Interactive simulation laboratory.

Deadlock occurs when processes wait mutually forever on resources. The Banker’s Algorithm prevents deadlock by simulating the future: a request is granted if and only if a complete finishing order (safe sequence) remains guaranteed.

Safe State Guarantee

An execution sequence $P_{s_1}, P_{s_2}, \dots$ exists such that every active process can obtain its maximum declared Need, execute to completion, and return all held allocations to the Available pool.

Transactional Tentative Grant

A proposed request is tentatively deducted from Available and credited to the process. The safety algorithm verifies whether the new state has a safe path. Unsafe? The allocation rolls back instantly with zero leakage.

Banker’s Algorithm Architectural Guide & Invariants

Mathematical Vector Definitions

Let $n$ be the number of processes and $m$ be the number of resource types:
• Available $[m]$: If $\text{Available}[j] = k$, then $k$ instances of resource type $R_j$ are free to be assigned.
• Maximum $[n \times m]$: If $\text{Max}[i][j] = k$, process $P_i$ may request at most $k$ instances of $R_j$.
• Allocation $[n \times m]$: If $\text{Alloc}[i][j] = k$, process $P_i$ currently holds $k$ instances of $R_j$.
• Need $[n \times m]$: $\text{Need}[i][j] = \text{Max}[i][j] - \text{Alloc}[i][j]$. Remaining resources $P_i$ may need to finish.
• Conservation Law: $\forall j \in [0, m-1],\; \text{Available}[j] + \sum_{i=0}^{n-1} \text{Alloc}[i][j] = \text{Total}[j]$.

The Safety Verification Algorithm (Work & Finish)

1. Let $\text{Work} = \text{Available}$ and $\text{Finish}[i] = \text{false}$ for all active processes.
2. Find an index $i$ such that $\text{Finish}[i] == \text{false}$ and $\text{Need}_i \le \text{Work}$. If no such $i$ exists, go to Step 4.
3. $\text{Work} = \text{Work} + \text{Allocation}_i$; $\text{Finish}[i] = \text{true}$; repeat from Step 2.
4. If $\text{Finish}[i] == \text{true}$ for all $i$, the system is in a safe state with a valid safe sequence.

Unsafe State vs. Deadlock

An unsafe state is not inherently deadlocked. It merely means the operating system can no longer guarantee that deadlock will be avoided if processes simultaneously demand their full declared maximums. The Banker's Algorithm prevents this possibility entirely by forbidding transitions into unsafe states.
